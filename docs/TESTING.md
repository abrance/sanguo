# 无头测试

游戏是纯前端的，但**规则层完全不依赖 DOM**，所以能在 node 里跑。
`tools/` 下三个工具都不需要安装任何依赖。

```bash
node tools/verify.js        # 一键自检（63 条断言），失败退出码非 0
node tools/verify.js -v     # 附明细
node tools/sim.js           # 被动玩家长跑 200 回合
node tools/sim.js --bot     # 主动玩家长跑
```

---

## `tools/harness.js`：装载器

它**直接解析 `index.html` 里的 `<script src>` 列表**来拼装源码，自动跳过 `js/view/**` 和 `js/main.js`（这两个碰 DOM）。
意义是：新增文件只要加进 index.html，测试就自动覆盖到，不会出现"忘了改测试"。

```js
const h = require('./harness');

const { api } = h.boot({ seed: 11, factionId: 'caocao', cityId: 'chenliu' });
const G = api.Store.get();

api.Store.dispatch('END_TURN');
console.log(G.meta.turn, api.State.troopCapOf(G, G.cities.chenliu));
```

`api` 里暴露了全部顶层全局：`State` `Store` `Combat` `Army` `AI` `Turn` `Rally` `TechSys` …（清单见 harness 顶部 `EXPORTS`）。

辅助函数：

| 函数 | 作用 |
|---|---|
| `boot(opts)` | 建局并 `Store.init`，返回 `{ api, get }` |
| `grantCities(api, n)` | 把 n 座别的城划给玩家，用于造多城场景 |
| `runTurns(api, months, each)` | 连续推进，捕获异常，返回 `{ ok, turn, error? }` |
| `scanNaN(api)` | 扫描所有城/玩家/军队的数值是否有限，返回问题列表 |

因为 `localStorage` 被替换成内存实现，`Save` 也能在 node 里测。

## `tools/verify.js`：断言集

八个板块，每条失败会打印原因：

| 板块 | 检查什么 |
|---|---|
| 状态不变量 | 70 城、势力无空白城、兵额拆解乘积 == `troopCapOf`、建筑镜像字段同步、士族数量与数值范围、开局科技乘数全 1 |
| 命令校验 | 9 条非法操作必须抛错（非直辖城建造、无船坞募水军、越级研科技、空选批量、补给线自指、县长转权臣、条件不足自立、无上命上缴）+ 2 条合法操作不抛 |
| 长跑 | 3 个种子各 80 回合，无异常且无 NaN |
| 战斗曲线 | 1:1 攻城胜率 <65%、1.5:1 在 60-95%、2:1 >85%、城墙 4 级时 1:1 <15% |
| 科技链 | 40 项、前置连成 10 层、可全研成、满树乘数在 1.5–4 之间 |
| 补给线 | 抽 90% 实际送 ≈90%、前线每月损兵时 ≥8/10 个月有兵在途、状态文案有语义、可取消 |
| 外交 | 中立不可攻、未宣战即攻=背刺（记仇 + 好感/声望扣罚）、关系不足不许结盟、结盟双向不可攻、同盟上限 2、停战期内不可攻且到期回中立、援军并入守军不开战、存档往返 `G.diplo` 完整、上命含出使/离间 |
| 外交长跑 | 200 回合无崩溃、世界出现过停战与结盟、停战期内无新发攻军、最大势力 < 60 城 |
| 存档往返 | 序列化 → `State.migrate` 后城数一致、新字段齐全 |

只要有一条挂了就说明改坏了东西。**提交前跑一遍。**

## `tools/sim.js`：平衡推演

```
node tools/sim.js [--months 200] [--every 20] [--seed 11]
                  [--faction caocao] [--city chenliu]
                  [--bot] [-v]
```

- 不带 `--bot`：**被动玩家** —— 只给直辖城设「均衡」方针，不做别的。用来测"不作为会怎样"。
- 带 `--bot`：**主动玩家** —— 每回合补兵到 95% 兵额、按军→农→工→商研科技、办上命、用满编城打最弱邻敌。

输出每 N 回合一行：势力数 / 最大势力 / 我方城数 / 官阶 / 战功 / 直辖 / 科技数 / 粮产乘数；
结束时打印胜负与数值检查结果。

### 当前基准（供对照）

```
被动玩家 seed 11：约 60 回合被吞（势力覆灭）      ← 不作为就该输
主动玩家 seed 22：200 回合时 曹操军 57/70 城，丞相  ← 会打就能赢
```

如果 `--bot` 跑出来 200 回合还在个位数城池，说明 AI 或经济被改崩了；
如果被动玩家能活到 200 回合，说明 AI 压力不足。

## 浏览器侧的验证

`tools/` 覆盖不到 Canvas 渲染与 DOM 交互。这部分要手工或用浏览器自动化：

```bash
python3 -m http.server 8080      # 起服务
# 打开 http://localhost:8080
```

必查四件事（改 UI 后）：

1. 控制台无报错
2. 点城 → 四个子页（概览/营造/士族/施政）都能渲染
3. 按钮禁用时能直接看到原因（如「步兵兵额上限 749」）
4. 推进 12 回合，纪事面板有输出、地图上能看到在途军队

## 已知的测试盲区

- **Canvas 渲染没有快照对比**，地形生成改了只能肉眼看
- **AI 决策没有单测**，只靠长跑观察宏观指标（外交长跑只验证「出现过停战/结盟」与兼并上限，不验证外交是否打得聪明）
- **平衡没有回归基线**，`verify.js` 里的胜率区间是宽区间，只能挡住"彻底崩坏"
- **手感无法自动测**：数值对不对和好不好玩是两件事
