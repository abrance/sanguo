## 1. 状态（三个新容器）

```js
G.events = {
  seen: {},              // eventId -> 上次触发回合（冷却用）
  pending: [],           // 延迟后果队列，见 §4
  log: [],               // 最近 30 条已触发事件（面板「史事」页读它）
  activeChain: null,     // 当前连锁根事件（防无限链）
};
G.court = {
  emperorCityId: 'luoyang',   // 皇帝所在城；null = 帝已失所
  controller: null,           // 当前控制帝都的势力 id；null = 无主
  edictTurn: 0,               // 上次矫诏回合
  abdication: null,           // { turn, askedTurn } 禅让进度
};
G.stats.eventsSeen = 0;       // 结局结算用
```

全部进 `META_DEFAULTS` / 新 `EVENTS_DEFAULTS`，`State.migrate()` 补默认值（旧档 = 空事件池，从下一回合开始抽）。

## 2. 触发与抽取

### 2.1 时机

回合流水线（`js/systems/turn.js`）末尾、纪事结算之后，新增一步：

```
... 现有各步 ...
N+1  事件抽取（最多 2 条）
N+2  延迟后果兑现（§4）
N+3  朝堂状态刷新（帝都归属、禅让计时）
```

放在最后的原因：事件要读「本月已经发生的战斗与经济结果」，才能写"本月蝗灾后粮少"这种因果文案。

### 2.2 抽取算法

```
1 收集候选：所有 event，过滤
   - once 且已触发过 → 丢弃
   - 冷却中（turn < seen[id] + cooldown）→ 丢弃
   - cond(G) 为假 → 丢弃
   - chain 限制：当前 activeChain 深度 ≥ 3 → 丢弃所有 chain 事件
2 权重：weight × scope 优先级系数
   player（你的直辖城）      ×3.0
   faction（你所属势力）      ×1.5
   world（全图）              ×1.0
3 抽 1 条；若 turn % 4 === 0（季度）再抽第 2 条
4 抽中后：seen[id] = turn，stats.eventsSeen++，activeChain 记根
```

玩家城优先级 ×3 的理由：全图事件多，玩家只对"我城里的事"有代入感。世界层事件靠历史锚点补。

### 2.3 事件对象 Schema

```js
{
  id: 'locust_190',
  name: '蝗灾',
  scope: 'player',                    // player | faction | world
  weight: 10,
  once: false,
  cooldown: 24,
  anchor: null,                       // 非空则忽略 weight，按回合窗口必触发（§8）
  cond: (G, ctx) => true,             // ctx = { cityId, factionId } 按 scope 给
  text: {
    title: '蝗虫蔽日',
    body: '……（2-3 句，可读 ctx 数值）',
    portrait: 'locust',               // 程序化剪影 key，见 §6.2
    source: '县丞急报',               // 卡片右下角的来源
  },
  options: [ /* 见 §3 */ ],
}
```

`ctx` 由系统按 scope 填：`player` → 随机一个你的直辖城；`faction` → 你所属势力；`world` → null。

## 3. 选项的强制约束（这是闭环的核心）

```js
{
  key: 'relief',
  label: '开仓赈济',
  costText: '粮 −800 · 治安 +6',
  cost: (G, ctx) => ({ food: 800 }),      // 返回 null = 不可选
  why: '粮不足 800',                      // 不可选时的原因（必填，否则按钮会静默失效）
  require: (G) => true,                   // 门槛（名望/官阶/路线）
  requireWhy: '需名望 ≥ 120',
  apply: (G, ctx) => ({
    logs: ['你把仓门打开，饥民跪了一地。'],   // 立即纪事（至少 1 条）
    fx: g => { /* 立即效果 */ },
    delay: { turns: 3, fx: g => {}, log: '赈济之粮告罄，各县又报缺粮。' },
  }),
}
```

**四条硬规则**：

1. **每个选项至少一项代价**（钱/粮/建材/兵/治安/关系/名望/战功/上限/宝物）。唯一例外是 `acknowledge` 型（见 §8 历史锚点）。
2. **代价必须前置显示**：`costText` 是玩家点之前看到的全部代价摘要，不许有"点了才知道"的扣费。
3. **不可选必须写原因**：`cost` 返回 null 时必须给 `why`，按钮渲染成置灰 + 原因（现有 `peace.js` 已有此模式，照抄）。
4. **每个选项立即写 ≥ 1 条纪事**，延迟后果到期再写 1 条。

选项数固定 2-3 个（1 个没有选择，4 个以上读不完）。

## 4. 延迟后果（让"选择"有重量）

```js
{ turns: 3, due: 该回合数, fx: (G) => {}, log: '一句话' , id: 'uid' }
```

规则：

- 写入 `G.events.pending`，`due = G.meta.turn + turns`
- 每回合按 `due` 升序兑现，兑现后必写 `log`
- **上限 40 条**；超出时最早的直接兑现（不许静默丢弃 —— 那等于暗改）
- 存档保存（`pending` 里的 `fx` 是函数，**不能序列化** → 存 `{ due, eventId, optionKey, turns }`，读档时按 id 回查事件表重建 `fx`；这是硬约束，写代码时别想着直接 `JSON.stringify`）
- 一个事件最多挂 1 条延迟后果（防止选项变成"期货合约"）

---

## 5. 连锁

```js
chain: ['refugee_190'],     // 本事件结算后，把下一个事件加进优先池
```

- 连锁最多 3 层（`G.events.activeChain.depth`），超出后新事件按普通池抽
- 同一 id 不在一局内连锁两次
- 例：`locust` → 3 月后 `refugee`（流民）→ 收留则 6 月后 `bandit`（盗匪，因治安低）

复用 `js/view/panels/peace.js` 的模态骨架（遮罩 + 居中卡 + 竖排按钮），新增：

- 键盘：`1/2/3` 选，`Enter` 确认，`Esc` 不关闭（必须选一个，除 `acknowledge` 型可 Esc）
- 减少动效（`prefers-reduced-motion`）：不加缩放/滑入
- 弹出时**暂停其他操作**（模态），但可以「稍后处理」？→ **不做**。必须当场选，否则玩家会囤卡
- 若同回合抽到 2 条：串行弹（第一条选完再弹第二条），不并排

### 6.2 剪影 key（程序化，零素材）

`portrait` ∈ `locust | plague | flood | comet | scholar | accuser | bride | refugee | capital | seal | edict | abdicate | defector | duel | nightraid | steppe`

画法：Canvas 或 SVG 单色剪影（圆/方/三角/线组合）+ 4% 噪点，颜色走 `--ink-2`。**不做人物立绘**（那是素材依赖，VISUAL.md 已列为不做）。

### 6.3 「史事」面板

纪事面板加第二个标签「史事」（原日志保留）：

- 列表：回合 · 事件名 · 你选的选项 · 一句话后果
- 折叠：已兑现的延迟后果挂在对应事件下面
- 用途：玩家回看"这一局发生了什么"，也是结局史评的素材来源

## 9. 朝堂（Court）与矫诏

### 9.1 状态机

```
帝都 = G.court.emperorCityId（洛阳 ↔ 长安 ↔ null）
每回合刷新：
  owner = 该城 owner
  if（owner !== court.controller）court.controller = owner（易主 → 记纪事 + 全势力 relation 波动 5）
  若 court.emperorCityId 的城被攻破且 owner==='free' → emperorCityId 保持，controller=null
```

### 9.2 权限（按 controller 判定）

| 命令 | 权限 | 效果 | 代价 | 冷却 |
|---|---|---|---|---|
| `IMPERIAL_EDICT {aFid, bFid}` 矫诏号令 | controller 是你的势力 | a、b 两势力互宣战（关系压到 −40，写"理由"文案） | 名望−10；a、b 对你 relation−8 | 6 回合 |
| `IMPERIAL_APPOINT {heroId}` 任命 | 同上 | 敌将：loyalty−8、ambition+10；己将：bond+10、战功+15 | 忠臣路线 favor−6（"越权"） | 4 回合 |
| `SUMMON_SCHOLAR` 征辟名士 | 同上 | 免费得 1 名在野将到帝都（loyalty 50） | 无（但每局最多 3 次） | 8 回合 |

### 9.3 反制（闭环的关键：权力可被夺走）

- 别人打下帝都 → 你的矫诏权立即失效，所有由你矫诏产生的宣战**继续有效**（已成事实），但你 `reputation −20`（"矫诏事发"）并写一条天下级纪事
- 你失去帝都后的下一回合起，`IMPERIAL_*` 命令抛错「帝在 <势力> 手，不得矫诏」
- AI 也会用矫诏：AI 控制帝都时，每月 8% 用一次（目标选择遵循 `AI.md` 的宣战阈值）

### 9.4 UI

不新增按钮。**官阶台面板新增一节「朝堂」**：

```
┌ 朝堂 ────────────────────────────┐
│ 帝在：洛阳（曹操 控制）            │
│ 矫诏权：不在你手                  │
│ 你的选择：夺取洛阳可获矫诏权       │  ← 附地图跳转按钮（点击地图居中并高亮该城）
│ ─────────────                    │
│ [矫诏号令] [任命] [征辟名士]       │  ← controller 是你时可用
└──────────────────────────────────┘
```

## 11. 与现有回合流水线的接线（顺序即正确性）

```
1  行军推进 / 抵达结算
```

## 12. 验收（`tools/verify.js` 新增断言）

1. **抽取**：固定 seed + 固定状态 → 抽到的事件 id 可复现；`once` 事件全生命周期只触发 1 次
2. **代价**：每个选项的 `cost` 都能算出非空对象或返回 null 且带 `why`；遍历全部 16+6 条做静态检查（缺 `why` 直接报错）
3. **不可选**：资源不足时 dispatch 抛错且状态零改动
4. **延迟**：写入后 3 回合精确兑现；`pending` 超 40 条时最早一条被兑现而非丢弃
5. **存档**：存档 → 读档后 `pending` 长度一致，且下次兑现在同一回合
6. **朝堂**：帝都易主后 `controller` 变更；非 controller 调 `IMPERIAL_EDICT` 抛错
7. **锚点**：推到第 90 回合，6 条锚点事件 `seen` 全为真
8. **不暗改**：跑 120 回合后，`events.pending` 兑现的每条在 `log` 里都有对应记录（数量对账）
9. **长跑**：`sim.js --months 200` 无 NaN、无异常、事件数在 20-45 区间（过低=池子条件太严，过高=刷屏）
