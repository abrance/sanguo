# 人物层设计稿（P7-A：人情账 / 名望 / 登用 / 宝物 / 战法）

> 状态：**设计完成，未实现**。本文只写需求逻辑，不写代码。
> 目标：让 134 名武将不再是「六个数 + 一个特技字符串」，补上汉末霸业最值钱的那一层。
> 相关：[DESIGN.md](../DESIGN.md) 数值与阶段 · [ARCHITECTURE.md](ARCHITECTURE.md) 分层与命令 · [EVENTS.md](EVENTS.md) 事件层 · [VISUAL.md](VISUAL.md) 表现层

## 0. 设计约束（每个系统都必须答完这四问，答不上就不写）

| 问题 | 含义 | 不满足的后果 |
|---|---|---|
| **入口** | 玩家在哪个面板点哪个按钮触发 | 系统做了没人用 |
| **出口（回读）** | 数值改动在界面哪里能看见 | 玩家认为"没生效" |
| **失效兜底** | 钱不够 / 无目标 / 状态非法时怎么办 | 报错或状态半改 |
| **存档兼容** | 新字段进哪个 DEFAULTS、旧档怎么补 | 旧档读入即崩 |

另有三条全项目通用红线（沿用现有约定）：

1. **玩家爽感优先**：新增机制以「多一个选择 / 多一份加成」为主，惩罚只放在可预警、可干预的政治层。
2. **不暗改数值**：任何自动变化都要在纪事留一条，且玩家能查到原因。
3. **规则层不碰 DOM**：新逻辑进 `js/systems/`，新数据进 `js/data/`，新按钮进 `js/view/panels/`。

## 1. 人情账（Hero Relations）

> **✅ 已实现**（2026-10，`feat/hero-relations`）：字段 / 漂移 / 四个命令 / 叛变状态机 / 人物页 / 派生接线全部落地，
> `verify.js` 新增「人情账」板块 12 条断言。实现口径与本文一致；另修了一处越权（`Diplo.sendAid` 会从玩家直辖城抽兵）。

### 1.1 现状与缺口

`hero.loyalty` 字段**已经存在**（`state.js` 创建时 60–95 随机、`clans.js` 征辟时置 78），但**从未被任何逻辑读取** —— 是个死字段。这就是最省力的切入口：不新增概念，直接把已有字段接活。

### 1.2 状态（`G.heroes[id]` 扩展）

| 字段 | 类型 | 初值 | 含义 |
|---|---|---|---|
| `loyalty` | 0-100 | 已有 60-95（在野 0） | 对所属势力的忠诚。低于 30 是危险区 |
| `ambition` | 0-100 | 见下公式 | 野心。高野心的人忠诚掉得快、易自立、难招 |
| `bond` | 0-100 | 见下 | 与**玩家**的私交。只有玩家势力内的将才有意义 |
| `grievance` | 0-9 | 0 | 积怨层数（被你责罚的次数，可消除） |
| `idle` | int | 0 | 连续闲置月数（既非守将也未出征），用于"久不任用" |
| `lastAct` | int | 0 | 上次被赏赐/责罚/提拔的回合数，用于冷却 |

初值（创建时一次算定，不每回合重算，保证同 seed 可复现）：

```
ambition = clamp(round(zhi*0.45 + wu*0.35 - mei*0.30 + RNG.between(-8, 8)), 5, 95)
bond     = 玩家直辖城守将 45 / 同势力其他将 30 / 在野 0 / 敌对势力 5
```

例：吕布（武100 智26 魅60）→ 野心 ≈ 33；司马懿类（智高武中魅低）→ 野心 ≈ 75 以上。**智勇高、人缘差的将最有野心**，符合直觉。

### 1.3 每月漂移（新文件 `js/systems/relations.js`，回合流水线插在「上级好感」之后）

```
drift = 0
 +0.4   本势力近 6 月净得城 > 0（在赢）
 -0.6   本势力近 6 月净失城 > 0（在输）
 -ambition / 200          （野心 80 → 每月 -0.4）
 +bond / 300              （私交 90 → 每月 +0.3）
 -grievance * 0.5
 +0.5   所在城学宫 ≥ 3 或 城治安 ≥ 80（有教化）
 -1.0   本将 idle ≥ 6（久不任用，从第 6 个月起才扣）
loyalty = clamp(loyalty + drift, 0, 100)
```

`bond` 与 `loyalty` 互相牵引（每月 10% 靠拢），避免两者长期背离：

```
bond += (loyalty - bond) * 0.10
```

`idle` 计数：本回合既不是某城 `governor`、也不在任何 `army.heroId` 里且未参与事件 → +1，否则清零。

### 1.4 玩家指令（4 个，全部 `Store.dispatch`）

| 命令 | 前置 | 花费 | 效果 | 冷却 |
|---|---|---|---|---|
| `REWARD_HERO {heroId}` 赏赐 | 该将在你直辖城 | 钱 80 × (1+官阶) 或 粮 400 | `loyalty +6, bond +10, grievance -1` | 同一人 3 回合 |
| `PROMOTE_HERO {heroId, cityId}` 提拔 | 你直辖城、该城换守将 | 战功 −5 | `bond +14, loyalty +4`；原守将 `loyalty -6` | 同城 6 回合 |
| `PUNISH_HERO {heroId}` 责罚 | 该将为你直辖城守将 | 无 | `loyalty -10, grievance +1`，本城 `order +3`（立威），同城其他将 `bond -3` | 同一人 5 回合 |
| `CONSOLE_HERO {heroId}` 抚慰 | `grievance > 0` | 粮 60 | `grievance -1, bond +5` | 同一人 3 回合 |

统一校验顺序（照现有命令风格，先校验后扣费，失败不改状态）：

```
1 该将存在且 alive，且 factionId === 玩家势力（PUNISH/PROMOTE 还要求是直辖城守将）
2 冷却已过（G.meta.turn >= hero.lastAct + cooldown）
3 资源足够
4 扣费 → 改值 → clamp → 写纪事 → 更新 lastAct
```

### 1.5 派生接线（这是「有用」的部分，必须逐条落到公式里）

| 派生 | 接在哪 | 公式 |
|---|---|---|
| 守城战力 | `combat.js` `power()` 守方 | `p *= 0.90 + loyalty / 500`（loyalty 100 → ×1.10，0 → ×0.90） |
| 出征士气 | `army.js` 建军时 | `morale = clamp(60 + (loyalty - 70) * 0.20 + 天赋, 20, 100)` |
| 城产出 | `economy.js` 守将生态 | `ecoBonus *= 1 + bond / 1000`（bond 100 → +10%） |
| 招揽他人 | 见 §3 | `+ bond * 0.5%` |
| 自立/投敌 | 见 §1.6 | — |

### 1.6 叛变状态机（唯一的"惩罚"，必须预警 + 可干预）

```
条件：loyalty < 30 且 ambition > 60 且 该将非玩家本人
每月掷：6%（loyalty<20 时 10%）
前置预警：满足条件的下一个月，先写一条纪事
          「<城><将> 心怀异志，恐生变故。」（每将 6 回合最多一条）
干预窗口：预警后的 3 回合内做过 REWARD / CONSOLE / PROMOTE / 换守将
          → 该将本回合「必定不叛」（安抚有效，仅一次）
叛变结算：
  a 若该将为守将且该城属于某势力 → 带城投奔：选与其所属势力 relation 最低、
    且与目标城相邻的势力（无则转为在野）
  b 否则 → 该将转为在野（factionId='free'，cityId=null），可被任何人登用
纪事两条：一条势力视角「<将> 举城降 <势力>」，一条天下视角（-关系 8）
```

**硬约束**：叛变**不许删将**。武将只能换主子或落草，不能消失 —— 否则玩家会"莫名其妙少了个名将"。

### 1.7 UI

- **城池面板新增第 5 个标签页「人物」**（现有：概览 / 营造 / 士族 / 施政）
  - 列表：`名 · 五维条 · 忠诚色条 · 野心小三角 · 特技 · 状态（守将/闲置 N 月/有积怨）`
  - 点一行 → 将卡浮层（复用现有浮层骨架）：五维、特技、忠诚/野心/私交三个条、五个宝物槽、四个指令按钮（不可用时按钮置灰并写明原因）
- **军务页选将**：忠诚 < 40 的将名字后加红点徽记，悬停提示「忠诚 X，不宜付以重兵」
- **纪事**：预警与叛变都进纪事，分类 `bad`
- 颜色一律走 CSS token（现有 `--bad / --good / --warn`），JS 不写色值

### 1.8 边界与兜底

| 情形 | 处理 |
|---|---|
| 旧档无新字段 | `HERO_DEFAULTS` 补 `ambition/bond/grievance/idle/lastAct`；`State.migrate()` 里按 §1.2 公式重算 ambition（用档内 seed，结果稳定） |
| 玩家本人 | 玩家是 `PLAYER` 伪将，不参与漂移与叛变（固定 100） |
| 全势力唯一守将叛变 | 允许，但城不会空 → governor 置 null，下月 AI/太守自动补任 |
| 在野将的 bond | 恒为 0，不做漂移（登用后才建立关系） |
| 数值越界 | 所有写点后 `U.clamp(0,100)`；`grievance` clamp 0-9 |

### 1.9 验收（`tools/verify.js` 新增断言）

1. `REWARD_HERO` 后 `loyalty/bond` 精确 +6/+10，钱按公式扣，冷却期内再调抛错且状态不变
2. 连续 6 回合不任用 → `idle=6` 且 `loyalty` 下降；重新任守将后 `idle` 归零
3. 构造 `loyalty=20, ambition=80` 的将 → 12 个月内必定出现至少 1 次预警，且预警后 3 回合内被安抚则该将不叛
4. 叛变后该将必存在于 `G.heroes`（`alive=true`，`factionId` 变为目标势力或 `'free'`）
5. 旧档迁移：无新字段的档读入 → 每将 `ambition ∈ [5,95]`，同 seed 两次迁移结果一致

## 3. 登用在野

> **✅ 已实现**（2026-10，`feat/hero-renown`）：访/礼/三顾三档命令 + 透明成功率（界面逐项列出）+ 连续三次失败后不再涨私交；
> 士族「征辟」改为同一套成功率（不再 500 钱必成功）。

### 3.1 现状（必须先认账，避免重复造）

已有 `CLAN_ACTION recruit`（士族面板"征辟"）：花 500 钱，**自动取五维最高的在野将，必成功**，士族满意 +7。它是一条"士族通道"，不缺。

缺的是**选择权**：玩家不能指定"我要徐庶"，也不能为一个名将多花力气。设计在这一层上做加值，不推翻原通道。

### 3.2 三档定向登用（新命令）

| 命令 | 花费 | 基础成功率 | 目标冷却 |
|---|---|---|---|
| `VISIT_HERO {heroId}` 拜访 | 钱 60 | 12% | 2 回合 |
| `GIFT_HERO {heroId}` 送礼 | 钱 260 + 粮 120 | 28% | 4 回合 |
| `BESEECH_HERO {heroId}` 三顾 | 钱 900 | 55% | 6 回合 |

成功率公式（**全透明**，UI 直接列出每一项）：

```
p = base
  + bond * 0.5%                目标与你的私交（在野通常 0）
  + reputation / 8 %           名望 200 → +25%
  + 玩家 mei / 4 %             魅力 60 → +15%
  + (100 - 目标 ambition) * 0.2 %
  - 目标 zhi * 0.15 %          聪明人难骗，智 95 → -14%
  + 关系修正：其原势力与你交战 +6%（走投无路）/ 同盟 -8%（不愿背盟）
clamp(3%, 92%)
```

**失败**：

- 钱粮不退（已花出去），但 `bond +3` —— "虽不见用，亦感其诚"
- 三顾失败额外 `reputation -3`
- 同一目标失败 3 次后，该目标的 `bond` 不再增长（"不堪其扰"），需舆情类事件解锁

**成功**：

```
h.factionId = 玩家势力
h.cityId = 指定城（默认你最近的直辖城，无则 homeCityId）
h.loyalty = 45 + bond / 2       // 自带私交加成
h.bond = max(bond, 20)
写纪事（一句中式独白，121 将各一条太贵 → 按五维分 4 档模板句）
```

### 3.3 原「征辟」的处理（改成一致的成功率，不保留必成功）

`CLAN_ACTION recruit` → 花 500 钱，候选为**当前城相邻地区**在野将（随机 1 名，不显示是谁，显示五维区间），成功率与三顾同档（55%）；失败仍给士族 `sat +3`。

理由：必成功的招募会掩盖整个名望/私交系统的价值 —— 五维最高的将被 500 钱直接买走，三档登用就没有存在意义。

### 3.4 边界

| 情形 | 处理 |
|---|---|
| 目标已被别人招走 | 抛错「<将> 已仕 <势力>」，列表刷新 |
| 目标就是你自己势力 | 抛错「已在麾下」 |
| 同时多条三顾 | 只允许 1 条在进行（`G.player.beseech = {heroId, until}`），防撒网式点击 |
| 在野将所在势力 `free` 无城 | 正常，在野将 `cityId=null` |
| 招来的将没有城可放 | 放到 `homeCityId`，若该城已丢 → 放到任一直辖城，全无 → 抛错（此时已亡国，走结局） |

### 3.5 UI

- 士族页「征辟」按钮保留
- 新增「访贤」按钮 → 全屏列表：在野将（名、五维、原势力、成功率、预计花费），行内三档按钮 + 失败次数标记

### 3.6 验收

1. 成功率公式对 3 个固定样本（弱名望低魅 / 高名望高魅 / 高智高野心）算出预期值，误差 0
2. 失败后钱扣了、`bond` 加了、目标 `factionId` 未变
3. 成功后将出现在指定城，`loyalty` 按公式
4. 同一目标连续 3 次失败后 `bond` 不再增长

## 4. 宝物（Treasures）

> **✅ 已实现**（2026-10，`feat/hero-renown`）：20 件 5 类、装备/卸下命令、`State.heroStat` 收口派生属性、
> 破城按 35% 留守/否则退往旧主治所、上级好感 >85 时 2% 赐宝、人物页槽位与装备入口。
> 未做：商人天赋花 600 买一件（需要开局界面入口）、AI 自己装备（见 §10）。

### 4.1 数据（新文件 `js/data/treasures.js`，20 件）

```js
{ id: 'qinggang', name: '青釭剑', cat: 'weapon', rare: 2,
  eff: { wu: 4 },                 // 只加派生属性，不改本体五维
  about: '削铁如泥，曹操令夏侯恩负之。' }
```

| 类 | 件数 | 主要效果 | 例 |
|---|---|---|---|
| `weapon` 兵器 | 5 | `wu +2…+6` | 青釭剑、丈八蛇矛、方天画戟 |
| `armor` 甲胄 | 4 | `tong +2…+4`，守城再 `+3%` | 明光铠、兽面吞头铠 |
| `mount` 坐骑 | 4 | 行军 `speed +8…15%`，`cav` 战力 `+5%` | 赤兔、的卢、爪黄飞电 |
| `book` 典籍 | 4 | `zhi +3…+6`、`zheng +2…+3` | 孟德新书、孙子兵法 |
| `seal` 印绶 | 3 | `mei +3…+5`，登用成功率 `+4%` | 传国玺、汉寿亭侯印 |

`rare` 1-3，只影响掉落权重与边框色，不影响数值曲线陡度（数值已按 rare 写死）。

### 4.2 获得（四条通道，每条都必须能回读）

| 通道 | 规则 |
|---|---|
| 破城 | 攻破带宝之城，35% 掉 1 件（按 rare 权重 3:2:1），进你的宝物池；`定宝城` 在 `cities.js` 里写 `treasureId` 字段 |
| 事件奖励 | 事件选项 `gain: 'treasure'`，从池里随机未持有的一件 |
| 上级赏赐 | 好感 > 85 时，每月 2% |
| 花钱购得 | 开局天赋「商人」可花 600 买 1 件随机（只 1 次，给正向选择，符合口味） |

### 4.3 装配

```
hero.slots = { weapon:null, armor:null, mount:null, book:null, seal:null }
treasure.holder = heroId | null      // 全局唯一持有者
```

- `EQUIP_TREASURE {heroId, treasureId}` / `UNEQUIP_TREASURE {heroId, cat}`
- 同类替换自动卸下原位（一件宝一次只在一个将身上，换人必须显式卸下）
- 派生读取集中到 `State.heroStat(G, heroId, key)`：`本体五维 + Σ 宝物 eff`。**战力公式只准读这个函数**，不许直接读 `h.wu`

### 4.4 边界

| 情形 | 处理 |
|---|---|
| 将叛变/被俘 | 宝物**留在原城**（不跟随叛将，否则资敌滚雪球）；被俘将的宝物归俘获方 |
| 持有宝物的将死亡 | `alive=false`，宝物回收到该将所在城的池 |
| 旧档 | `treasure.holder` 缺省 null；`hero.slots` 缺省全 null（`HERO_DEFAULTS`） |
| 同一件装两个将 | 命令层拦截「宝物已被 <将> 持有」 |

### 4.5 UI

- 将卡浮层 5 个槽位（空槽虚线框 + 类名），点击 → 按类筛选的宝物列表
- 城池面板「概览」加一行「城内宝物 N 件」（未装备的池）
- 宝物边框按 `rare` 用 token（`--rare-1/2/3`，新增三个 token 进 `:root`）

### 4.6 验收

1. 装备后 `State.heroStat` 精确增加，卸下复原，`Combat.power` 随之变化

### 5.1 先修一个真 bug（Step 1，半天，不新增任何东西）

> **✅ 已实现**（2026-10）：`feat/hero-skills-wiring`，新增 13 条断言（`verify.js`「武将特技接线」板块）。
> 顺带修了一处行为矛盾：`Legion.run` 的「征讨」按注释应「不掷骰子、当回合出兵」，但代码仍卡在胜算闸门上 ——
> 现改为带 `force` 时忽略 `pred.win` / `pred.remain`（AI 常规出兵不受影响）。

`TAODONG190_HERO_SKILLS` 声明了 11 个特技、20 个效果键，但**全项目只有 4 个键被读取**：

| 键 | 状态 |
|---|---|
| `atk` `def` `defenseCity` `economy` | ✅ 生效 |
| `cavalry` `archer` `infantry` `navy` | ❌ 从未被读（`combat.js` 里那段 `byType` 用技能 id 去索引技能对象，键写错了，永远 falsy） |
| `siege` `morale` `enemyDef` `enemyAtk` | ❌ 从未被读 |

后果：颜良文丑的「突击」、太史慈文聘「神射」、周瑜「水战」全是纯文案。

**接线规格**（改 `combat.js` + `army.js`）：

```
兵种键（cavalry/archer/infantry/navy）：p *= 1 + (sk[key]-1) * 该兵种兵力占比
siege   ：攻击方 p *= sk.siege（火计 1.20）
morale  ：army.js 建军时 morale *= sk.morale（扬威 1.15）
enemyDef：敌方战力结算时 p *= sk.enemyDef（火计让敌防 ×0.92）
enemyAtk：同上，敌攻 ×0.90（急智）
```

原则：**宁可改数据也不留假文案**。接完线再上战法，否则战法是在一个"特技不起作用"的战场上叠新概念。

### 5.3 规则（闭环）


**必须改造的那一步**：`Combat.resolve` 现在一口气算完 6 轮并返回全部行。要支持轮间干预，需改成：

```
Combat.round(G, atkState, defState, roundNo) → { lines, atkLoss, defLoss, done }
```

## 6. 数值平衡原则

1. **新增益优先给玩家可选**：赏赐、提拔、登用、宝物、战法都是"玩家主动花资源换增益"，不做无条件的全局加成。
2. **AI 也吃同一套规则**（人情账、宝物、战法），但呆在后台算，玩家不感知 → 世界的"人味"对双方一致，避免"只有我有"的廉价感。
3. **单条加成上限**：任何单一来源对同一 refine 数值的加成 ≤ +20%（宝物 +6 武力 ≈ 战力 +3%，战法单轮 ≤ +50% 但只一轮）。防止出现"一件宝物定胜负"。
4. **惩罚必须有出口**：忠诚低 → 有赏赐/责罚/换将三条路；叛变 → 有 3 回合预警窗口。
5. **不新增第 5 种资源**。战法消耗士气、登用消耗钱粮、名望是积分不是货币。
